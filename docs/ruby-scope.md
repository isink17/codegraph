# Ruby scope model

With the tree-sitter Ruby parser, CodeGraph records nested class/module identities, singleton and instance methods, definition-site lexical nesting, and supported visibility and constant-mutation facts. Ruby calls use Ruby-specific resolution; generic repository-wide name matching does not fill its unsupported cases. The non-CGO heuristic Ruby parser retains symbol/import extraction and does not produce call edges.

Implicit calls and literal `self` calls bind only to a unique method of the caller's exact semantic container and matching instance/singleton nature. Constant receivers first resolve the constant identity, then its singleton method. Relative constant lookup follows the source method's recorded lexical nesting, innermost first; explicit root and multi-segment constant paths are also supported when every segment has coherent declaration and visibility evidence. An inner constant shadows an outer constant even when the inner constant lacks the requested method. Constant receivers require a provably public singleton target; implicit/literal self receivers can reach their own private/protected methods.

Reopened class/module declarations can share a semantic constant. Duplicate method definitions do not establish a runtime winner, so an otherwise eligible call stays unresolved. Contradictory constant kinds, ambiguous lexical nesting, incompatible visibility evidence and recognized literal constant-mutation hazards also prevent binding. Production callers exclude test-only targets and test-only mutation evidence. These are static repository facts; a resolved edge does not prove that a particular application execution loaded the target.

`require` and `require_relative` strings are retained as import metadata. They do not grant lexical visibility, supply generic import scope or create cross-language links from Ruby. CodeGraph does not simulate Ruby's load path, execution order or required-file execution. An independently supported cross-file Ruby target can bind from its qualified declaration facts; a require is neither necessary nor sufficient evidence for that binding.

Rails/Zeitwerk filename conventions do not add resolution evidence. Loader configuration and custom inflection can change the path-to-constant mapping, and CodeGraph does not reconstruct that runtime mapping. Recognized literal `autoload` forms are treated as constant-identity hazards rather than as permission to infer a target.

The model does not implement complete Ruby constant lookup or runtime dispatch. Deferred shapes include cref-ancestor lookup and implicit Object/top-level fallback, inheritance and mixin method lookup (`include`, `prepend`, `extend`), general value/chained/safe-navigation receiver typing, calls without a modeled source method, dynamic `const_set` names or receivers, semantic expansion of `eval`/`class_eval`/`send`, `const_missing`, `method_missing`, and runtime load-order decisions. Explicit `::Constant` lookup is distinct from implicit Object fallback and can be supported.

Literal mutation guards cover recognized syntax, including supported assignment, `const_set`, `remove_const` and `autoload` forms. They are not a general detector of indirect runtime mutation: dynamic or metaprogrammed changes can invalidate static assumptions without producing a hazard fact. Treat the graph as a partial static model rather than proof of full Ruby runtime behavior.
